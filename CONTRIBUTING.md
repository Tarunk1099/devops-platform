# Contributing

## Workflow

1. Create a separate branch for each change.
2. Make focused, meaningful commits.
3. Test changes before opening a Pull Request.
4. Describe the change and its purpose in the Pull Request.
5. Merge changes only after review and required checks pass.

## Branch Naming

Use descriptive branch names, such as:

- `feature/add-health-check`
- `fix/deployment-status`
- `docs/update-readme`

## Commit Messages

Use Conventional Commit prefixes:

- `feat:` for new features
- `fix:` for bug fixes
- `docs:` for documentation
- `chore:` for maintenance

## Quality Expectations

- Keep changes focused and readable.
- Never commit passwords, tokens, or other secrets.
- Update documentation when behavior or setup instructions change.
